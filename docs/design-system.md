# Context Mixer デザインシステム「台所(Daidokoro)」 v0.3

UIプランA(HTMX案)の土台となるデザインシステム。実体は `public/tokens.css`(CSSカスタムプロパティ)で、このドキュメントはその意図と判断基準を記す。プレビューは `/design`(public/design.html)で確認できる。

---

## 1. コンセプト

**「よく使われる台所」 — 雑多な素材を歓迎し、読むときは静かに味わう。**

ここに入ってくるのは清書された文書だけではない。かき捨てのメモ、AIが書き散らしたログ、貼り付けただけの断片が大半を占める。Context Mixer(ミキサー)という名のとおり、この場所は**素材置き場であり調理場**だ。よく使われる台所は、素材が雑多に持ち込まれても破綻せず、道具はすぐ手に取れる場所にあり、そして出来上がったものは落ち着いて味わえる。

デザインの仕事は2つ。**雑多なものを「未完成で恥ずかしいもの」に見せないこと**。そして**読むときには静かな品質で味わえること**。判断に迷ったら次の4原則に従う。

1. **即応 > 演出** — アニメーションより応答速度。待たせる演出は作らない
2. **本文 > UI** — 画面上で最も濃い色は本文テキスト。UI部品は本文より目立ってはならない
3. **構造は罫線と余白で** — カード・影・グラデーションで区切らない。区切りが必要なら細い罫線か余白を使う
4. **走り書きが様になる** — 構造のない3行のメモも、整った長文と同じ品位で表示される。レイアウトや装飾が「ちゃんとした文書」を前提にしてはならない

## 2. 方向性

- **紙の質感に寄せた配色**: 純白ではなく生成り(わずかに暖色の白)。長時間の読みで目が疲れない
- **色は墨+藍の二色構成**: テキストは墨色、インタラクティブ要素(リンク・ボタン・現在地)だけが藍。「青いものは押せる/今ここ」という一貫したルール
- **システムフォントのみ**: Webフォントは配信しない(表示スピード最優先と矛盾するため)。日本語はOS搭載のヒラギノ/Noto Sans JPに任せる
- **ダークモードはOS追従**: 手動トグルは作らない(必要になったら足す)
- **アイコンは線画(Lucide)を最小限**: 意味が自明な場所のみ。基本はテキストラベル

### 2.1 ソリッドライン(アナログ7 : デジタル3)

生成り+本のアナログ感をベースに、CLIアプリのソリッドさを2〜3割混ぜる。**線引きは「本文は常にアナログ、UIクロームだけデジタル」**。

- **機械の事実は等幅**: 日時・パス・作者・件数・コレクション名(構造名)は `--font-mono`。人間の文章は常にサンセリフ。「等幅で書かれているものはシステムの発言」という一貫ルール
- **日時はISO風**: `2026-06-12 21:17`(JST固定)。ロケール表記は使わない
- **直角に近い角**: `--radius-sm: 2px` / `--radius-md: 4px`
- **骨格線の強弱**: ヘッダー下・サイドバー境界だけ `--border-strong`(1段濃い)。中身の区切りは薄い `--border` のまま。フレームの輪郭だけが固い
- **プロンプト記号 `❯`**: 検索入力の左に。藍色・等幅
- **やらないこと**: レトロターミナル演出(緑文字・スキャンライン・ASCII罫線)、UIラベルの等幅化、本文への適用

### 2.2 ベタ+白抜きブロック(最強の視覚要素、用途は2つだけ)

ベタ塗りに白抜き文字のブロックは画面で最も強い。装飾には使わず、**意味のある機械的事実にだけ**割り当てる。

1. **作者タグ** (`.author-tag`): メタ行の `ai:キー名` は藍ベタ白抜き(このサービスで最も重要な事実=AIの署名)。human は枠線のみの控えめ表示
2. **システム行のエラー** (`.sysline.is-error`): エラー時のみ赤ベタ白抜き。「強い色が出た=何かが起きた」を成立させるため、平常時に赤ベタを使わない

(ブランドロゴは別途制作予定。完成までベタブロックの3つ目の枠はロゴ用に予約)

### 2.3 システム行(sysline)

右下に出る等幅・細枠の1行メッセージ。トーストの代替であり、**UIではなくシステム自身の声**というレイヤー。

- 形式: `✓ 追記しました — 21:17`(等幅・細枠・右下固定)
- 成功は4秒で消える。エラーは赤ベタ白抜きで8秒
- サーバーは `HX-Trigger: {"sysline": "メッセージ"}` で発火する
- 同時に1つだけ。連発しない(直前のものを置き換える)

### 2.4 雑多さの扱い(原則4の具体化)

- **見出しゼロ・数行のドキュメントでも様になる**: 目次は見出しが2つ未満なら自動で消える。メタ情報(日付・パス)は1行に収め、本文が3行でもページとして貧相に見えないこと
- **ツリーのデフォルトは更新順**: フォルダの整理を使う者に強要しない。「最近触ったものが上にある」だけで雑多な置き場は機能する
- **archiveは薄く沈める、消させない**: priority=archive のドキュメントは `--text-muted` で表示して視界から退かせる。削除を促すUIは作らない(かき捨ては資産になる)
- **書く場所は「メモ帳」**: ツールバー付きエディタではなく、ただのtextarea。書き始めの儀式をゼロにする
- **AIの書き込みを二級市民にしない**: author(human/AI)表示は muted の小さな注記に留める。AIが書いたことを警告風に強調しない(8割はAIが書く前提のサービスである)

## 3. デザイントークン

実装は `public/tokens.css`。命名は `--役割-変化形`(例: `--text-muted`)。**生の色値をコンポーネントで直接使わない**こと。

## 4. コンポーネント原則(抜粋)

- **リンク**: 本文中は常時下線(`text-underline-offset: 3px`・細線)。UI(ツリー・ナビ)は下線なし+hover時に `--surface-dim` 背景
- **ボタン**: 3種のみ。primary(藍地白字・1画面に原則1つ)/ default(罫線のみ)/ quiet(罫線もなし、アイコンボタン等)。danger は default の色違い
- **入力欄**: `--surface` 地+罫線。フォーカスは `--accent` の2pxアウトライン(`:focus-visible`)
- **ツリー項目**: 現在地= `--accent-subtle` 背景+左2pxの藍バー。hover= `--surface-dim`。展開▸は項目高さいっぱいをタップ領域にする
- **状態表示**: 成功は何も出さない(完了が見えれば十分)。失敗のみトースト。「裏で更新中」は右上に小さな点インジケータ1つ
- **バッジ(inbox未承認等)**: 藍地の小円+数字。装飾用バッジは作らない

## 5. 運用ルール

- 新しい色・サイズが欲しくなったら、まず既存トークンで済まないか考える。足す場合はこの文書とtokens.cssの両方に追記する
- ページ固有CSSでトークンを上書きしない
- このシステムが対象とするのは読み画面・ツリー・検索・キャプチャ。管理画面(keys/inbox)は同じトークンを使うが、コンポーネントの作り込みはしない

## 6. 癖 — 結びの「了」

本文(`.prose`)の末尾には、必ず薄い墨色で**「了」**が一字、中央に打たれる。

昔の書物が文の終わりに打った終止符。機能は何もない。読み込み状態の表示でもなければ、ステータスでもない。**不合理であることを認めた上で、これはこのプロダクトの署名として残す。**

- 3行の走り書きにも、長編の設計書にも、同じ「了」が打たれる。どんなかき捨てメモも、読み終えれば一篇の文章として扱われる(原則4が最も不合理な形で現れる場所)
- 「了」が付くのは本文表示(`.prose`)のみ。検索スニペット・リンクプレビュー・編集中のtextareaには付けない。**読み終わりにだけ現れる**こと
- 実装はCSSのみ(`.prose::after`)。本文データには含まれない(APIで取得するMarkdownは汚さない)
- これ以上「癖」は増やさない。2つ目の癖は癖ではなく散らかりである
